## The engine contract the app consumes (load-bearing — read the header)

- `engine/include/sequencer_engine.h` is the single source of truth for Swift
  (committed; cbindgen). 8 `extern "C"` entry points + `#[repr(C)] EngineResult`
  (`Ok=0, ErrDecode=1, ErrInvalidHandle=2, ErrInvalidBuffer=3, ErrOther=4`).
  `EngineHandle` is a COMPLETE struct (`uint8_t _private[0]`) → Swift must type
  `engine_new()` as `UnsafeMutablePointer<EngineHandle>?`, NOT `OpaquePointer?`.
- **Bytes, not structs.** Commands (Swift→Rust) and Events (Rust→Swift) cross as
  **postcard** bytes. You need a Swift postcard codec matching the Rust
  `Command`/`EngineEvent`/model layouts exactly (the in-progress `Engine/Postcard/`
  + `PostcardTests` are the place to verify byte-exactness).
- **Drain framing:** `engine_drain_events` yields **one event per call**
  (postcard bytes; freed by `engine_free_bytes`, exactly once). Empty/zero-length
  = drained. Pull-only — no push callback. Drain ~120 Hz on a dedicated
  DispatchQueue, **coalesce `Playhead` per-track (track_idx→step_idx, latest per
  frame)**, one MainActor hop per batch (E7). Small events (`Playhead`,
  `PlayStateChanged`, `BpmChanged`, `SyncSourceChanged`, `PatternSwitched{index}`,
  `UndoAvailable`, `Overflow{dropped}`) come on the hot channel; `Serialized` /
  `FullSnapshot` on the large channel (drained second).
- **Lifecycle:** `engine_start` spawns RT + state-worker + CoreMIDI threads;
  `engine_stop` joins all three (returns BEFORE `engine_free`); `engine_free`
  defensively joins-then-drops. `engine_submit_command` enqueues (drop-oldest +
  `Overflow` on overflow). `engine_serialize` is synchronous (bytes out via
  non-NULL params). Gestures → commands; the UI never mutates engine state.
- **Rule 7:** Swift owns the `MIDIClientRef` + endpoint discovery; pass integer
  endpoint IDs to the engine via `SetMidiDestinations`. The engine owns its own
  internal send-client+port. (On-device `MIDISend` validation procedure:
  `docs/midi-on-device-validation.md`.)

## Build environment — will bite you on the first command

Homebrew rust shadows rustup on this machine. Before ANY cargo/rustc/cbindgen
command: `export PATH="$HOME/.cargo/bin:$PATH"` (the committed
`engine/scripts/*.sh` self-export). Build the **app** with `-sdk iphonesimulator`,
NOT `-destination 'generic/platform=iOS Simulator'` (no simulator runtime
installed). Flow:

```bash
cd app && xcodegen generate && xcodebuild -project StepForge.xcodeproj \
  -scheme StepForge -sdk iphonesimulator -derivedDataPath build \
  CODE_SIGNING_ALLOWED=NO build
```

The xcframework is **linked** (not embedded); CoreMIDI.framework linked; the
Swift bridging header points at `engine/include/sequencer_engine.h`. (Disk was
~5 GB free during engine work — watch it; clean `target/` if a build disk-fills,
